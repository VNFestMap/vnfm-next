# 第一期范围（只做这些）

当前只实现五块：**用户**、**同好会（创建与加入）**、**活动**、**通知**、**中国/日本地图**。其余功能冻结，等项目所有者以后逐项打开。实现或评审时以本文为准；`01`–`03` 是原站全量清单，不是这一期的待办。

打开冻结项必须改本文，不能在业务 PR 里顺便做。

对应模块：`Platform`（会话、本站用户、通知、R2）+ `Club`（目录、会籍、中国/日本地图）+ `Ops` 的活动子域。Wiki / Social / Program / Edge / catalog / 赛事 / GalOnly 全部不开工。江苏子地图、亚洲底图、联合星图仍冻结。

---

## 做

### 1. 用户

登录注册不在本站表单里做，跳 NextMoe 账户中心（OIDC）。本站只做 Relying Party 和本站资料面。

| 做 | 说明 |
|----|------|
| 登录 | 跳 `account.nextmoe.com` `/oauth/authorize`（PKCE）；回调换票；本站会话 cookie |
| 注册 | 跳账户中心注册，回来走同一套 authorize |
| 登出 | 清本站会话；可选再跳 OP 登出 |
| 看自己 | 用户中心：OIDC 缓存的公开资料（id、名、头像 URL）、本站会籍、报名的活动、未读通知 |
| 改本站信息 | 代表同好会、语言、主题。入会申请邮件开关若做邮件再开，本期不做邮件 |
| 改账户主档 | **链接到账户中心**（改名、头像、邮箱、密码）。本站不提供这些表单，也不把 OIDC 头像上传到 R2 |

不做：本地用户名密码、QQ/Discord 绑定、找回密码、资料完整度七项计分、壁纸库、地图反色。

身份主键 = userinfo 的整数 `id`。本站 `users` 只存这个 id + 本站列。IdP 的 `roles` 不授权。

### 2. 同好会：创建与加入

能找到组织、建一个、申请进去、负责人审人。**不要**把原站社团详情上的社区插件一并做掉。

| 做 | 说明 |
|----|------|
| 目录 | 列表、关键词、按国家/省份（或日本县）筛选、类型筛选。中日 `(id, country)` 成对 |
| 详情 | 名称、地区、学校、类型、介绍、头像、联系方式按可见性规则脱敏、申请按钮 |
| 创建 | 已登录用户创建，自己成为 `representative`。资料写入本站库，头像走 R2 |
| 申请加入 | 填联系方式与理由；`pending` → 负责人通过/拒绝 |
| 绑定码 | 负责人生成/吊销；用户兑换后直接 `active` |
| 会籍管理 | 成员列表、改角色（`member` / `manager` / `representative` / `external`）、踢人、转让负责人、退出 |
| 编辑资料 | `manager` / `representative` 改本社介绍、头像、联系方式可见性 |

联系方式：非成员默认隐藏；`protected` 仅正式成员或本社管理者可见。外交 `external` 不算正式成员。

不做：江苏子地图、亚洲底图、联合星图 / 星盟、留言板、神器榜、萌王位、公开分享卡、growth 仪表盘、Bot Token、江苏批量、投稿审核队列（旧 `submit.html`）、超管「审核中心」。原首页上的海外 / 企划枢纽 / 论坛 / 广场 / GalOnly / Wiki 入口不要做成半成品按钮。

### 2b. 中国 / 日本地图

原站首页是全屏 SVG 地图 + 叠加层（顶栏、简介卡、省份抽屉、地图/列表切换）。这一期把这套布局接回来，并画中国、日本两张图。

| 做 | 说明 |
|----|------|
| 首页布局 | 全视口地图底图；顶栏（头像/登录/账号、地图↔列表、中国/日本/活动日历）；左侧可收起简介；右侧省份抽屉（搜索、类型、排序、组织列表）；列表模式三分栏（简介、地区索引、卡片网格）；移动端汉堡抽屉 + 底栏抽屉 |
| 中国地图 | 原 `china.js` 路径；按省着色（数量越多越深）；数量徽章；平移缩放；点省打开右侧列表 |
| 日本地图 | 原 `japan.js` 路径；按都道府县同样交互 |
| 数据 | 公开 `GET /clubs` + `GET /clubs/regions` 统计各省/县数量。创建同好会时省份/县用规范名，才能对上地图 |

不做：江苏 13 市钻取、亚洲底图、海外同好会页、地图气泡二级菜单、地图反色。

### 3. 活动

通用活动日历，挂在同好会上。不是 GalOnly，不是企划枢纽。

| 做 | 说明 |
|----|------|
| 浏览 | 公开列表 + 日历或按日筛选 |
| 发布 | 本社 `manager` / `representative` 增删改；关联 `ClubRef` |
| 报名 | 登录用户报名/取消；用户中心能看到「我报名的」 |
| 截止 | 活动开始或报名截止后锁定，不能再改报名 |

不做：公开投稿待审（旧 `submit_event.html`）、与企划合并展示、活动海报专题页。

### 4. 通知

只做站内信，打通上面三条业务。

| 做 | 说明 |
|----|------|
| 存储与接口 | 列表、未读数、已读、全部已读 |
| 入会 | 新申请 → 管理者；通过/拒绝/踢出/改角色 → 当事人 |
| 活动 | 报名成功（给报名人）；可选：本社新活动发给成员（不要做成广播垃圾，默认只给报名人即可） |

不做：邮件/SMTP、全站公告 `announcements`、论坛/Wiki/赛事类通知（那些模块冻结）。

- R2：社团头像、活动封面；账户头像不进 R2

catalog **本期不做**（即使 04 写了「按需」）。

## 和原站的刻意差异

- 创建同好会：原站只有超管直接入库、路人走投稿队列。本期 **登录用户可直接创建并成为负责人**，减少第一期对超管台的依赖。

- 账户主档不搬进本站：改名改头像去 nextmoe。

## 验收（第一期可上线的路径）

1. 未登录能看首页地图（中国/日本）、点省看组织、切到列表模式；也能看公开活动。联系方式按规则隐藏。
2. 点登录/注册 → 账户中心 → 回本站已登录。
3. 用户中心能看到自己的会籍、报名、通知；改代表同好会/主题生效；改名入口指向账户中心。
4. 登录用户能创建同好会、改资料、发绑定码。
5. 另一用户能申请加入；负责人通过后对方成为成员；也能兑换绑定码加入。
6. 负责人能发活动；成员能报名；截止后报名锁定。
7. 申请/审核/踢人会产生站内通知，可标已读。

做完以上就停。不要接着做江苏子地图、Wiki、广场或赛事。
